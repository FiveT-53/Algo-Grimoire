# 验证说明

## 运行方法

在仓库根目录运行，文档检查只需 Node.js，无需安装 npm 依赖：

```text
node scripts/check-docs.mjs
node scripts/check-examples.mjs
node scripts/check-solutions.mjs
```

第三条还需要支持 C++20 的 g++，也可以通过环境变量 CXX 指定兼容命令行参数的 clang++。代码块按 LeetCode 的 Solution 格式组织，脚本自动补充头文件、命名空间和驱动，在系统临时目录编译并清理产物。编译器缺失或断言失败会返回非零退出码，不会把跳过算作通过。

## 检查范围

- check-docs：检查 Git 已跟踪 Markdown 的一级标题、标题层级、代码围栏、行尾空白、引用列表格式、本地文件和图片路径、简单标题锚点。不是完整 Markdown lint，不检查网络链接、复杂内联标题渲染或语义正确性。
- check-examples：读取 16 篇题解的输入、输出，用独立枚举核对文中小规模示例；这项验证的是题面示例，不是 C++ 代码。
- check-solutions：提取 16 篇题解中的实际 C++ 代码（包含第 3 题的两个版本），运行示例与边界断言；对 930、1248 枚举长度不超过 8 的二进制/奇偶数组，用二次枚举作为独立参考检查计数。
- GitHub Actions：推送或 PR 时依次执行以上三项。配置存在不等于远端运行已通过。

二分文件目前是未跟踪的个人草稿，不属于默认检查范围。纳入版本管理时，应增加空数组、全重复值、目标不存在、首尾命中与整数极值的测试；通用 upper_bound 实现应避免依赖可能溢出的 target+1。

## 维护约定

每篇新题解保留一个核对过的示例和至少一个边界案例，并把断言加入 check-solutions。草稿与模板不宣称运行通过。记录平台提交结果时保留日期和语言版本；性能比较需控制输入、编译选项和重复次数，单次平台排名不作为优化证据。
